# 课程地图

## 课程定位

本课程面向已经学过 Python、线性代数和深度学习基础，希望进入 AI 系统软件与算子开发的高年级本科生、研究生和高校教师。重点是把“能运行的算子”推进到“正确、可编译、可扩展、可测量的算子”。

## 进入课程前

建议具备：

- Python 与 PyTorch 张量操作；
- 矩阵乘法、Softmax、LayerNorm、RMSNorm；
- 线程、内存层次、带宽与延迟的基本概念；
- Git、命令行和基础性能测试经验。

缺少 GPU 编程经验也可以参加。模块 1 会建立 host/device、grid、tile、mask 和 reduction 的共同语言。

## 模块依赖

| 学习阶段 | 需要掌握 | 为下一阶段提供什么 |
|---|---|---|
| 1. Triton 基础 | program/grid、tile、mask、reduction、GEMM | 一个正确且可调参的 kernel |
| 2. 算子工程 | 融合、反向、Dispatcher、`torch.compile` | 从 kernel 进入框架执行栈 |
| 3. 编译器 | 图捕获、DSL、MLIR、TTIR/TTGIR、lowering | 解释配置如何影响生成代码 |
| 4. 分布式系统 | DP/TP/PP/ZeRO、collective、拓扑、α-β 模型 | 把算子代价放进多卡训练 |
| 5. 性能工程 | Benchmark、Roofline、Profiler、Amdahl | 形成可复核的优化闭环 |

## 学习节奏

每个模块都按四步推进：

1. **预习**：读模块 README 的概念地图和指定课件页。
2. **讲授**：围绕一个核心问题串联概念，避免只背组件名称。
3. **实践**：完成代码、IR 追踪、通信推演或性能实验。
4. **验收**：提交证据、解释结果并说明适用边界。

五天集中课建议每天 6 小时；常规学期课可拆成 10 次，每次 2.5–3 小时。具体安排见 [课表](SCHEDULE.md)。

## 贯穿全课的问题

- 正确性由什么测试证明，边界 shape 是否覆盖？
- 性能数据的计时边界、公平性和统计口径是什么？
- 当前结论来自数学模型、编译器观察、硬件实测，还是课件中的经验范围？
- 单 kernel 的收益能否穿过框架、通信和端到端执行路径？
- 换一类硬件或软件版本，哪些结论仍成立，哪些必须重测？

## 结课能力

完成课程后，学生应能：

- 使用 Triton 编写并验证基础算子；
- 为 GEMM 设计有依据的参数搜索，而非盲目枚举；
- 实现带前向、反向和框架注册的融合算子；
- 解释 `torch.compile` 到 Triton/MLIR/LLVM 的主要链路；
- 估算并行训练的显存占用和集合通信成本；
- 用 Benchmark、Roofline 和 Profiler 给出一致或相互修正的性能判断。
